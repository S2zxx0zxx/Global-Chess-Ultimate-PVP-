# P03 advanced search

All eight P03 tasks are in scope, not P04. Independent implementation of standard chess search concepts; original package used as mechanism reference, no copied C# or media. Retain chess.js and existing P02 strategies. VITE_AI_ADVANCED_SEARCH=true opts in to depth-three iterative search; default legacy compatibility remains until mode rollout. Max depth 6, max q extension 8, max nodes 50,000, max engine budget 2,000ms, existing 120ms controller grace. No TT or P04 move-ordering heuristics. Deterministic seeded ordering only.

Negamax uses side-to-move scores, mate distance, terminal-before-evaluation. Quiescence searches captures/promotions and all legal evasions when checked (subject to alpha-beta pruning); no stand-pat while checked. At unresolved checked frontier cap abort the iteration, keep previous completed line. Nonchecked capped frontier uses static evaluation. All moves undone in finally; cumulative nodes across iterations; deadline checked before node and between moves, including history replay. Worker hard-stop is still a separate wall-time backstop; cold startup and browser scheduling can extend round trip. Full PV replay validates legal and terminal sequence; mate scores must match terminal PV. No new backend or dependency.

Tests include independent exhaustive shallow minimax, force-mate oracle, interrupted depth, 1ms/2s fake-clock deadlines, node bounds, legal PV, terminal draw, recapture and promotion. Browser measures fixed seed, same seven positions, paired foundation vs advanced, three rounds per mobile viewport, deadline and actual resumed computer game. Bounded recursion and no unbounded cache establish structural memory limits, not measured heap or physical Android certification. Full performance/memory and P04 optimization gates remain separate. Do not claim Elo or production readiness.
